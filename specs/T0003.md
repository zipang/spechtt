# T0003 — Bun Subprocess STT Worker on Top of Vercel AI SDK (`src/stt/`)

## Context & Goal

SpeechTT delegates remote Speech-to-Text (STT) provider streaming to a lightweight, stateless **Bun subprocess (`src/stt/worker.ts`)** built on the **Vercel AI SDK (`ai`)** (`PRODUCT.md` §5, §6 Phase 6, §7).
- `bun` is assumed pre-installed on the user's machine (`bun run src/stt/worker.ts`); no compiled JS binary is needed.
- Communication with the Rust host (`speechtt-core`, see `specs/T0002.md`) uses **full-duplex Newline-Delimited JSON (NDJSON) over `stdin` and `stdout`**, with `stderr` reserved strictly for human-readable diagnostics.
- The **first target** is the **Vercel AI SDK (`ai`)** (`experimental_streamTranscribe` for live streaming transcription models via Vercel AI Gateway / provider SDKs, with a seamless fallback to `transcribe` for segment/batch models such as Mistral Voxtral).

## 2. NDJSON Protocol Contract (`src/stt/protocol.ts`)

Must match `crates/speechtt-core/src/protocol.rs` (`specs/T0002.md`) byte-for-byte.

### Inbound Commands (`stdin`, Rust → Bun)

```ts
export type InboundCommand =
  | {
      type: "start";
      sessionId: string;
      provider: string;     // e.g. "vercel" | "openai" | "xai" | "elevenlabs" | "mistral"
      model: string;        // e.g. "openai/gpt-realtime-whisper" | "xai/grok-stt" | "voxtral-mini-transcribe-3-0"
      sampleRate: number;   // e.g. 16000
      apiKey?: string;      // Optional override from Rust settings store; falls back to process.env
    }
  | {
      type: "audio";
      pcm16Base64: string;  // Base64-encoded 16-bit little-endian mono PCM chunk (~40-50ms)
    }
  | { type: "pause" }
  | { type: "resume" }
  | { type: "stop" };
```

### Outbound Events (`stdout`, Bun → Rust)

```ts
export type OutboundEvent =
  | { type: "ready" }
  | { type: "started"; sessionId: string }
  | { type: "partial"; sessionId: string; text: string }
  | { type: "delta"; sessionId: string; delta: string }
  | { type: "committed"; sessionId: string; text: string }
  | { type: "stopped"; sessionId: string; fullText: string }
  | { type: "error"; sessionId?: string; code: SttErrorCode; message: string };

export type SttErrorCode =
  | "invalid_protocol"
  | "missing_api_key"
  | "unsupported_provider"
  | "stream_failed"
  | "aborted";
```

### Security & Logging Rules
1. **`stdout` is strictly for NDJSON**: `emit(event: OutboundEvent)` writes `JSON.stringify(event) + "\n"` to `process.stdout`. Never call `console.log` in any module imported by the worker.
2. **`stderr` is for diagnostics**: Use `console.error("[stt-worker]", ...)` for debug/warning logs.
3. **Never log `apiKey`**: Provide a `redactCommand(cmd: InboundCommand)` helper so any diagnostic logging of `"start"` replaces `apiKey` with `"[REDACTED]"`.

## 3. Vercel AI SDK Streaming Architecture (`src/stt/adapters/vercel-ai-sdk.ts`)

### Why Base64 Chunks Map Zero-Copy into the AI SDK
In the Vercel AI SDK (`ai`), `experimental_streamTranscribe` accepts:
```ts
audio: ReadableStream<Uint8Array | string>
inputAudioFormat: { type: 'audio/pcm', rate: sampleRate }
```
When `audio` yields `string` chunks, the AI SDK treats each string as **base64-encoded raw PCM bytes**. Because Rust already sends `{"type":"audio","pcm16Base64":"..."}`, the Bun worker can enqueue `cmd.pcm16Base64` **directly into the `ReadableStream<string>` without decoding or re-encoding buffers**!

### Audio Stream Controller & Pause/Resume Gate (`src/stt/stream-controller.ts`)

Create an `AudioStreamBridge` class that wraps a `ReadableStream<string>` and an `AbortController`:
- **`pushAudio(pcm16Base64: string)`**:
  - If `paused === true` or `closed === true`, drops the chunk (or optionally enqueues silence if a provider requires keepalive frames).
  - Otherwise calls `controller.enqueue(pcm16Base64)`.
- **`pause()` / `resume()`**:
  - Toggles the `paused` gate so audio frames arriving during a transition are ignored while paused.
- **`close()`**:
  - Closes the `ReadableStream` (`controller.close()`), causing `experimental_streamTranscribe` to flush its final transcript and resolve `result.text`.
- **`abort()`**:
  - Triggers `abortController.abort()` if the session is torn down abruptly (e.g., `stdin` EOF).

### Consuming `experimental_streamTranscribe` in Real Time

Per the AI SDK documentation:
> *"`fullStream` is a single-consumer live stream and can only be accessed once. When you need both stream parts and final results, access `fullStream` first and await the result promises while or after consuming it."*

```ts
import { experimental_streamTranscribe as streamTranscribe } from "ai";

const result = streamTranscribe({
  model: resolveModel(config), // e.g. 'openai/gpt-realtime-whisper' or provider instance
  audio: bridge.readable,      // ReadableStream<string> (base64 PCM16 chunks)
  inputAudioFormat: {
    type: "audio/pcm",
    rate: config.sampleRate,
  },
  abortSignal: bridge.abortSignal,
  headers: buildAuthHeaders(config),
});

emit({ type: "started", sessionId: config.sessionId });

let accumulated = "";

for await (const part of result.fullStream) {
  switch (part.type) {
    case "transcript-delta":
      emit({
        type: "delta",
        sessionId: config.sessionId,
        delta: part.delta,
      });
      break;

    case "transcript-partial":
      emit({
        type: "partial",
        sessionId: config.sessionId,
        text: part.text,
      });
      break;

    case "transcript-final":
      accumulated = appendSegment(accumulated, part.text);
      emit({
        type: "committed",
        sessionId: config.sessionId,
        text: part.text,
      });
      break;
  }
}

// Once `stop` closes `bridge.readable`, `fullStream` finishes and `result.text` resolves:
const finalText = (await result.text) || accumulated;
emit({
  type: "stopped",
  sessionId: config.sessionId,
  fullText: finalText,
});
```

### Fallback for Non-Streaming / Batch Transcription Models (`transcribe`)
Some models (e.g., `mistral/voxtral-mini-transcribe-3-0` or `openai/whisper-1`) use the batch `transcribe()` API rather than a live WebSocket `experimental_streamTranscribe` endpoint:
- In `src/stt/registry.ts`, mark each model's mode as `"streaming"` (`experimental_streamTranscribe`) or `"segmented"` (`transcribe`).
- For `"segmented"` models, the adapter accumulates base64 PCM chunks into a sliding/periodic buffer (e.g. every ~2–3 seconds of active speech and on `pause` / `stop`), wraps the PCM bytes in a minimal 44-byte WAV header, calls `transcribe({ model, audio: wavBytes })`, and emits `committed` + `stopped` events using the exact same `OutboundEvent` contract.

## 4. Worker Loop & Lifecycle (`src/stt/worker.ts`)

Design the main loop as a pure async function for deterministic testing:

```ts
export async function runWorkerLoop(
  lines: AsyncIterable<string>,
  emit: (event: OutboundEvent) => void,
  adapterFactory: SttAdapterFactory = defaultAdapterFactory,
): Promise<void>
```

### Lifecycle Rules
1. On startup, immediately emit `{"type":"ready"}`.
2. Maintain at most one active `SttSession` at a time:
   - **`start`**: If a previous session is still open, close/abort it first. Validate credentials (`config.apiKey || process.env[providerEnvVar]`). If missing, emit `{"type":"error","sessionId":...,"code":"missing_api_key","message":...}` and stay alive for the next command. Otherwise start the adapter session.
   - **`audio`**: Forward `pcm16Base64` to the active session's `AudioStreamBridge`.
   - **`pause`**: Pause the active session's `AudioStreamBridge`.
   - **`resume`**: Resume the active session's `AudioStreamBridge`.
   - **`stop`**: Call `await activeSession.stop()`, which closes the input `ReadableStream`, awaits the final `stopped` emission, and clears `activeSession`.
3. On `lines` completion (`stdin` EOF when the Rust parent exits): abort any active session and return cleanly (exit code `0`).

### T3.2 — Protocol (`src/stt/protocol.ts`)
- `parseInboundLine` returns a discriminated result (`{ ok: true, command }` or `{ ok: false, code: "invalid_protocol", message }`) instead of throwing, so the worker can keep reading after bad input.
- Validation covers required `start` fields, positive integer `sampleRate`, optional string `apiKey`, and padded standard base64 for `audio`.
- Parse errors never echo the raw line (it may contain an API key); `redactCommand` returns a copy with `apiKey: "[REDACTED]"`.

### T3.3 — Registry (`src/stt/registry.ts`)
- Providers: `vercel`/`gateway` (`AI_GATEWAY_API_KEY`, then `VERCEL_AI_GATEWAY_API_KEY`), `mistral`, `openai`, `xai`, `elevenlabs`.
- `resolveProviderApiKey` prefers the explicit `start.apiKey`, then the provider env vars in order; whitespace-only values are ignored.
- Known models map to `streaming` (`openai/gpt-realtime-whisper`, `xai/grok-stt`, `elevenlabs/eleven-scribe-2-realtime`, ...) or `segmented` (`mistral/voxtral-*`, `openai/whisper-1`, ...); unknown models fall back to the provider default.

### T3.4 — Streaming adapter (`src/stt/stream-controller.ts`, `src/stt/adapters/vercel-ai-sdk.ts`)
- `AudioStreamBridge` exposes `readable`, `abortSignal`, `pushAudio` (returns whether the chunk was enqueued), `pause`, `resume`, `close`, and `abort`; `abort` errors pending reads and is a no-op after `close`.
- `VercelAiSdkAdapter` accepts injectable `streamTranscribe` and `resolveModel` functions. Default resolution uses `createGateway({ apiKey })` for gateway/vercel and the direct provider factories otherwise, so an explicit `start.apiKey` is honored.
- Stream parts map to `partial`/`delta`/`committed`; `stopped` uses `result.text` when non-empty and otherwise the accumulated segments. Provider failures emit one `stream_failed` error and still emit `stopped`; synchronous SDK throws are emitted from `start()` without crashing.

### T3.5 — Segmented adapter (`src/stt/adapters/mistral.ts`)
- `createWavHeader`/`pcm16ToWav`/`pcm16Base64ToWav` produce the canonical 44-byte header (PCM=1, mono, 16-bit, little-endian sizes).
- `MistralAdapter` accumulates PCM16 and flushes every ~2.5 s (configurable via `segmentSeconds`), on `pause`, and on `stop`, then emits `committed` and finally `stopped`.
- Default model resolution uses `@ai-sdk/mistral` for Mistral sessions and the shared provider resolver for other segmented models (for example `openai/whisper-1`). Errors emit `stream_failed` and never reject `stop()`.

### T3.6 — Worker (`src/stt/worker.ts`)
- `runWorkerLoop` emits `ready` immediately, keeps at most one active session, validates provider/API key before starting, and stops the previous session before a new `start`.
- `stop` awaits `session.stop()`; EOF aborts the active session and returns cleanly. All command handling is guarded so malformed input or adapter failures produce `error` events instead of terminating the process.
- CLI entrypoint runs only when `import.meta.main` is true and reads NDJSON lines from `Bun.stdin.stream()` via `decodeLines`.
